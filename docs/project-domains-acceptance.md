# Projects, domains, and HTTPS acceptance

Run this on an installed candidate on each supported platform: macOS, Windows, and the Linux terminal edition. Use a disposable local account or machine. Record the OS, browser versions, installer hash, and build commit. These checks must use the OS resolver and normal browser trust; do not use `curl --resolve`, `--cacert`, or `-k` as substitutes.

1. Ordinary usage: with no projects, create `fairway/www/plain/index.php`, start Fairway, and open `http://127.0.0.1:8800/plain/`. Confirm startup, Start all, and Stop all never ask for OS elevation and leave the hosts file and trust store unchanged.
2. Outside the document root, create `~/code/shop/public/index.php` that echoes `$_SERVER['REQUEST_URI']`, plus `~/code/shop/.env`. Choose **Add project** (Linux: `fairway project add shop ~/code/shop/public --index`), pick `public` with the folder picker, enable **Route missing paths to index.php**, read the hosts explanation, and approve the OS request. Open `http://shop.test:8800/courses/1` in a normal browser: it must reach `index.php`. Confirm `/.env` and `../.env` paths are not served and that only `shop.test` was added inside Fairway's marked hosts block.
3. Decline: add a second project and cancel the OS request. Confirm the project stays listed as "Address not set up yet", **Set up addresses** appears, and HTTP for `shop.test` still works. Retry and approve.
4. Edit: rename the second project's domain. Confirm one approval replaces the old hosts entry with the new one and the old domain stops resolving. Edit only the name or web root and confirm no OS prompt appears.
5. Enable HTTPS for `shop` after reading the trust explanation. Open `https://shop.test:8443/` in the platform's normal browsers without ignoring certificate errors: Safari and Chromium on macOS, Edge and Firefox on Windows, Chromium and Firefox on Linux. Record whether each browser trusts the certificate. A browser warning is a failure to investigate, not a pass. Cancel the trust prompt once and confirm HTTPS stays off with an error, HTTP keeps working, and retrying works.
6. Turn HTTPS off. Confirm HTTP still works and **Remove certificate trust** appears; use it and confirm the trust store no longer lists Fairway's CA.
7. Move `~/code/shop` away. Confirm the project shows as unavailable without being removed, Nginx still serves other sites, and editing the web root recovers it. Remove the project and confirm its folder and files remain and its hosts entry is gone, while unrelated hosts entries are untouched.
8. Configuration failure: make the web root unreadable or otherwise force `nginx -t` to fail while saving. Confirm the error is shown, the previous project list is kept, and `http://127.0.0.1:8800/` keeps working.
9. Uninstall while keeping data. On macOS, test both the interactive path and `--yes-keep-data`; on Windows, test the normal and silent NSIS paths; on Linux, run the bundled uninstaller. Confirm Fairway's hosts block and CA trust are gone, while projects, databases, and backups remain. Reinstall and confirm projects are listed with HTTPS off and **Set up addresses** offered. On macOS, also test the optional delete-data path after trust cleanup.

Retain the browser result, hosts-file before/after diff with unrelated entries redacted, trust-store verification, and installer lifecycle result with the candidate. Do not merge based only on source tests or the smoke test's forced DNS/certificate options.
