# Project domains and HTTPS acceptance

Run this on an installed candidate on each supported platform: macOS, Windows, and the Linux terminal edition. Use a disposable local account or machine. Record the OS, browser versions, installer hash, and build commit. These checks must use the OS resolver and normal browser trust; do not use `curl --resolve`, `--cacert`, or `-k` as substitutes.

1. Create `fairway/www/plain/index.php` with a distinctive response. Create a Laravel fixture with `artisan` and `public/index.php`; keep a private file beside `artisan` that must not be served through its `.test` site.
2. Start Fairway and refresh projects. Confirm `http://127.0.0.1:8800/plain/` still works, and that refresh neither asks for OS elevation nor changes the hosts file. Confirm the Laravel site's root is `public/` in the generated Nginx configuration.
3. Choose **Enable** beside `plain.test` only (or run `fairway domain plain on` on Linux). Read the explanation, approve the OS request, and open `http://plain.test:8800/` in a normal browser. Confirm `laravel.test` was not added to Fairway's managed hosts block. Then enable `laravel.test` and confirm both domains return their own fixtures, the Laravel private file is inaccessible, and the localhost URL still works.
4. Enable HTTPS for one project after reading the trust explanation. Open `https://plain.test:8443/` in the platform's normal browsers without ignoring certificate errors: Safari and Chromium on macOS, Edge and Firefox on Windows, Chromium and Firefox on Linux. Record whether each browser trusts the certificate and whether the site is served correctly. A browser warning is a failure to investigate, not a pass.
5. Turn HTTPS off for the project. Confirm HTTP still works and that the UI's stated persistent trust behavior matches the OS trust store. Re-enable HTTPS and test again.
6. Turn off HTTPS for `plain` and remove its `.test` address. Confirm `laravel.test` keeps working, `plain.test` is removed from Fairway's marked hosts block, and unrelated hosts entries remain untouched. Delete the `laravel` folder and refresh projects; refresh alone must not change the hosts file. Confirm the unused `laravel.test` address remains visible in the UI and can be removed separately.
7. Uninstall while keeping data. On macOS, test both the interactive path and `--yes-keep-data`; on Windows, test the normal and silent NSIS paths; on Linux, run the bundled uninstaller. Confirm Fairway's hosts block and CA trust are gone, while projects, databases, and backups remain. On macOS, reinstall and also test the optional delete-data path after trust cleanup.

Retain the browser result, hosts-file before/after diff with unrelated entries redacted, trust-store verification, and installer lifecycle result with the candidate. Do not merge based only on source tests or the smoke test's forced DNS/certificate options.
